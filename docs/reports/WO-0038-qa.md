### R-3. MAX_MESSAGE (10-3-max-message.txt)

`dispatch.compose(item, root, message_ref)` builds the text: the header, then a pointer with the item id, the absolute work-order path, the report path and the lifecycle line. The goal and the done criteria are never inlined, so a long mission does not change the length. Measured by importing `mesh.dispatch` from the repo with `python3 -B -I`:

| case | bytes | limit | headroom |
|---|---|---|---|
| HEADER alone | 1000 | 4096 | 3096 |
| 3990-char goal + 10 long criteria, default paths | 1587 | 4096 | 2509 |
| same + long work-order and report paths | 1693 | 4096 | 2403 |
| report path near MAX_TEXT (3900 chars, legal in Scope) | 5468 | 4096 | -1372 |

Over the limit, `mesh/tools.py:608-613` (`work_dispatch`) raises `InvalidArgs("the composed message is larger than 4096 bytes (the projmux limit); shorten the work-order or report path")`. It does this before `_apply(... DispatchSend ...)`, so nothing is sent and the state does not change. A grep for `larger than` in tests/ finds no test for this refusal (R3).
