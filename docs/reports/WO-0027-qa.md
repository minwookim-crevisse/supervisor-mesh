## Modelling assumptions (where the design is ambiguous)

1. D100, D104 and D105 refusals are guard refusals that write nothing, like D68 and D81. The design names no route for them.
2. D101's review trigger allows any class. The written reason is the step label, not a record field.
3. D104: "scope/depends revised" and "done criteria revised" are a nondeterministic revision kind in the step label. An item blocked by `dependency_cancelled` has no failure class, so it needs no class-specific revision.
4. D105: commit lineage is a block of ten integers per attempt base. Merges, rewrites and a moving base are not modelled.
5. D106: the config may still change between a pin and `start`; that `start` is then refused as `inputs_changed` (D100).
6. Deps' reject is limited to the reply and flag triggers, as a scope cut for run time. D101 is covered elsewhere (section 4).
