# WO-0001 — Security review: Slack bridge 0.1.2 draft

- Role: security lead (verifier). One security worker did the first pass; the lead re-checked every finding against the code with separate loopback probes.
- Scope: `templates/slack/slack_bridge.py`, `templates/slack/env.example`, `skills/slack-setup/SKILL.md`, `tests/test_slack.py`, DEC-0005, the Slack section of the QA report, the Slack lines in `README.md`, `.gitignore`, `scripts/scrub.sh`.
- Method: read the code, then run probes against a local loopback HTTP server with FAKE token values. No real token or `.env` was read, no live Slack call was made, and the repo was not modified apart from this report. Scratch files were removed.
- Python 3.12.3.

## Claims CONFIRMED (lead-verified)

- **C1:** The token is not in argv or the environment. Lead ran `watch` as a subprocess against the loopback server and read `/proc/<pid>`: `C1 token in cmdline: False | in environ: False`. Gap J's *behaviour* is closed.
- **C2:** The token is never in a URL. GET params are only the call params (`:71`); the token is only in the header (`:67`).
- **C3:** Error and exception messages carry no token. `raise … from None` (`:84`, `:86`) drops the HTTPError/URLError chain. Probe: JSONDecodeError message contains no token. The worker also probed HTTP 500, a bad scheme, a refused connection and a unicode token, with no leak.
- **C4:** The misnamed-`.env` hint lists file NAMES only (`:47-48`, glob of names, no read).
- **C5:** State holds only `floor` and `threads` timestamps; the leaf dir is 0700 (probe above).
- **C6:** `.gitignore` ignores `.env` / `.env.*` and keeps `.env.example`: `git check-ignore -v` → `.gitignore:2:.env`, `.gitignore:3:.env.* .env.txt`; `templates/slack/env.example` not ignored (exit 1). `env.example` has empty `SLACK_BOT_TOKEN=` / `SLACK_CHANNEL_ID=`.
- **C7:** No secret-like literal in the Slack files. `grep -rnE 'xox[abpre]-[A-Za-z0-9-]{8,}'` over the repo → no match (exit 1). The scrub hits are only S-11.
- **C8:** Bots, our own bot and edits (`message_changed`) are skipped (`HUMAN_SUBTYPES :37`, `is_human :151-154`).
- **C9:** The skill can only be invoked by the user (`disable-model-invocation: true`, SKILL:4).
- **C10:** `python3 -m unittest discover -s tests -p test_slack.py` → `Ran 15 tests … OK`, exit 0. This supports the review but does not prove any security property.

## Verdict

11 findings: 🔴 2 (S-01, S-02) · 🟠 5 (S-03, S-04, S-05, S-06, S-11) · 🟡 4 (S-07 to S-10).

**FAIL.** Not safe to ship until S-01 and S-02 are fixed. S-03 to S-06 should land in the same rework (WO-0004), and S-11 blocks the `make check` gate. Fixes go to the owning roles: backend for code and skill, orchestrator for S-11 and the DEC-0005 wording.
